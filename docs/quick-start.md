# Создать роль и назначить пользователя

Для локального сервиса выполните инструкции запуска из README репозитория. В примере сервер доступен на `http://localhost:8080`, а backend запущен с `DEV_ACTOR_ID=1`. Это локальный режим без проверки credentials. В рабочем окружении механизм идентификации нужно согласовать с backend.

## Получите каталог прав

```sh
curl 'http://localhost:8080/permissions?scope_type=project'
```

Ответ `200` — массив объектов с `code`, `scope_type`, `title`, `description`. Это доступные коды для формы, а не эффективные права текущего пользователя. Для выбора показывайте `title` и `description`, в запрос отправляйте `code`.

## Создайте роль

```sh
curl 'http://localhost:8080/roles' --json '{
  "name": "Наблюдатель",
  "scope": {"type": "project", "id": 10},
  "permission_codes": ["project.view"]
}'
```

Ответ `201` содержит созданную роль. Пример формы ответа:

```json
{
  "id": 7,
  "name": "Наблюдатель",
  "scope": {"type": "project", "id": 10},
  "permissions": [
    {"code": "project.view", "scope_type": "project", "title": "Просмотр проекта", "description": "Текст из каталога"}
  ],
  "version": 1,
  "created_by": 1,
  "created_at": "2026-11-23T10:00:00Z",
  "updated_at": "2026-11-23T10:00:00Z"
}
```

Тексты каталога в примере иллюстративные. Используйте фактические значения ответа. Сохраните `id` и `version`.

## Назначьте пользователя

```sh
curl -X PUT 'http://localhost:8080/roles/7/assignments/42'
```

Тело запроса не требуется. При первом назначении ответ `201`, при повторном — `200` с той же записью, автором и временем:

```json
{
  "role_id": 7,
  "user_id": 42,
  "assigned_by": 1,
  "assigned_at": "2026-11-23T10:01:00Z"
}
```

## Измените роль

```sh
curl -X PUT 'http://localhost:8080/roles/7' --json '{
  "name": "Редактор",
  "permission_codes": ["project.view", "project.edit"],
  "expected_version": 1
}'
```

Ответ `200` содержит обновлённую роль. Используйте её `version` для следующей записи. `PUT` полностью заменяет имя и набор прав. Для устаревшей версии сервер вернёт `409`: загрузите роль заново и предложите пользователю согласовать изменения.

## Отзовите назначение и удалите роль

```sh
curl -X DELETE 'http://localhost:8080/roles/7/assignments/42'
curl -X DELETE 'http://localhost:8080/roles/7?expected_version=2'
```

Оба успешных ответа — `204`, без JSON. В `expected_version` передайте последнюю полученную версию. Удаление роли также удаляет её назначения. Повторный отзыв назначения успешен, пока сама роль существует; после удаления роли отзыв вернёт `404`.
